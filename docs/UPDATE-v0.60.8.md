# v0.60.8 - активные сетевые объекты и персонажи в миссиях

## Исправления
- Во время панельной мини-игры игрок остаётся видимым другим игрокам на прежней позиции. stationaryWork блокирует управление, но не скрывает сетевого персонажа. Механики настоящего укрытия и дрона не меняются.
- Мяч в хабе больше не получает параллельные корректировки через поле bl и снимок мира, и нет повторного ручного удара удалённого игрока из hub-sync. Хост моделирует физику, гость получает состояния.
- Движущиеся объекты передаются в уже существующих пакетах 20 Гц, без новых сообщений: только изменения, до 32 объектов и 8 КиБ на пакет, с циклическим обходом. Если WebSocket переполнен, значения повторяются при следующей передаче. Обычный мир остаётся 5 Гц, восстановление ключевыми снимками каждые 3 секунды.
- На клиенте гости не двигают пассивные тела хоста при столкновении и не меняют их скорости. Коллизии сразу используют авторитетную физическую позицию, а графическая модель плавно догоняет её каждый кадр (с экстраполяцией не больше 85 мс).
- В хабе физические предметы сглаживаются каждый кадр рендера, а не только при очередном сетевом сообщении; ограниченные по расстоянию скачки телепортируются, чтобы не протягивать объекты через карту.

## Автоматические проверки
- Проверка изменения состояния, восстановления после перегрузки WebSocket, лимитов 32/8 КиБ, справедливой очереди и защиты от невалидных координат.
- npm run test:online, npm run build запускаются GitHub Actions перед деплоем main, а также на pull request. PR не публикуется на Pages автоматически.
- Cloudflare Worker, ветка release и отдельный Cloudflare Pages не менялись.

## Что нужно проверить в настоящем двухклиентском матче
1. Два игрока в хабе катят мяч и взаимодействуют с тележками; у обоих одинаковые позиции и результаты.
2. Каждый по очереди начинает панельную миссию: второй должен видеть неподвижного персонажа на том же месте во время выполнения, завершения и отмены.
3. При длительном движении и временных лагах сравнить F3/F8 (RTT, очередь, частоту и время обработки кадров). Проверить восстановление через ключевой снимок.
4. Проверить, что смена хоста и матч с ИИ не ломают владение объектами.

Это тестируемое изменение кода, но реальный WAN-пинг и отсутствие любых рывков на обоих устройствах нельзя гарантировать без совместного теста.
