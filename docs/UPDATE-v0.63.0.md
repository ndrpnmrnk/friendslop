# v0.63.0 - хаб без откатов и меньше работы в кадре

База main e5f34b4e1a8c9f4e1ab3db6f90ebe1d9fe6b7886. Изменения для main / GitHub Pages. Боевой release и Worker не публикуются.

## Исправления
- Для миссии «Граффити» проверяются и положение стены, и место, где должен стоять исполнитель. Обе точки должны оставаться внутри игровой сетки города; техническая область с внешними домами и запасом границы исключена. Прежние проверки свободного места, высоты и размера грани сохранены.
- Гость передаёт ведущему контакт с мячом или толкаемым объектом вместе с намеренной скоростью движения. Ведущий проверяет тип объекта, расстояние, высоту, занятость и допустимую скорость и применяет импульс к общему предмету. Произвольные координаты предметов от гостя не принимаются. Ограничение контактов - не чаще одного на предмет за 100 мс, внутри прежних пакетов движения.
- Для обычных подбираемых предметов добавлен тот же путь контакта. Подбор и бросок остаются прежними командами.
- При уходе из вкладки ведущий отправляет итоговый снимок хаба и явно освобождает роль ведущего хаба. При возвращении сначала запрашивает актуальное состояние у действующего ведущего и только после ответа снова сообщает о присутствии в хабе. Пропавший requestAnimationFrame больше не считается входом в матч.
- При смене ведущего очищаются прежние цели сглаживания. Старый интерполятор не тянет предметы к координатам предыдущего ведущего.
- Мяч голосования и другие первоначальные толкаемые объекты падают за островом. После падения ниже -14 м возвращаются в сохранённое исходное положение. Обычные подбираемые предметы используют такой же возврат. Новые копии не создаются, предметы в руках или под управлением игрока не перехватываются.
- Возврат реквизита тира и бочек выполняет ведущий. Гость не запускает собственный таймер возврата общего объекта.

## Оптимизация без изменения моделей и пресетов
- Столкновения толкаемых объектов ищут соседей в сетке 4 м, а не проверяют все возможные пары на карте. Большие объекты занимают все пересекаемые ячейки, повторные пары исключены. Ближняя физика столкновений сохранена.
- Неподвижная коллизия не пересобирается повторно. Принудительное обновление всей ветки матриц толкаемого объекта требуется только для связанных инстансов разрушаемого реквизита.
- Проверка земли под неподвижными предметами на столах и полках использует короткий кеш, как и предметы на земле. При изменении положения или начале движения опора проверяется снова.
- Матрицы сцены обновляются один раз перед отрисовкой. Основной проход, силуэт персонажа и наложенное фото используют готовые матрицы; повторный автоматический обход всей сцены исключён. Параметры качества и геометрия районов сохранены.
- Команды контактов не заставляют отправлять полный снимок мира при каждом толчке. Частота сетевых пакетов не повышена; дополнительно передаются только события передачи ведущего и восстановления.

## Проверка и границы результата
Сценарий scripts/online/hub-recovery.html запускает два настоящих клиента с локальным Worker. Проверяет толчок гостем большого мяча, удар по обычному предмету, подбор и бросок, уход и возвращение ведущего без отката, падение и возврат реквизита, границы граффити, пространственный поиск столкновений и смешанную карту с семью ботами.

Целевой сценарий - PASS: два клиента, толчки и бросок гостя, передача/возврат ведущего, падение и общий возврат предметов, проверка граффити, смешанный раунд с семью ботами без ошибок. В сценарии с 240 разнесёнными объектами проверена 1 соседняя пара вместо 28 680 возможных; соприкасающиеся бочки продолжают раздвигаться. Production build и 94 общих теста - PASS.

Среда использует настоящий код геометрии, физики и сети с CPU-моделью рендера. Это не замер видеокарты, 1% low или FPS на компьютере автора и не матч двух людей через интернет. Достижение 100 FPS пока не подтверждено. Если игра остаётся на 60 FPS, следующий шаг - сравнение F3 в одинаковом районе до/после и проверка частоты экрана; порог в 100 FPS нельзя обещать без такого замера.
