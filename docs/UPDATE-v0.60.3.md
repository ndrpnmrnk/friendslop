# v0.60.3 - общий мир: тестовая версия (29.10.2026)

Обновление предназначено для `main`. В `release` переносить только по команде автора.

## Что изменилось

- Генерация игровой карты отделена от случайности THREE UUID, текстур и кешированных моделей.
  У районов, городских жителей, начальных инструментов и погоды отдельные потоки случайности.
- Хост выбирает миссии и передаёт точные рецепты: id, вид, место, ссылку на объект, зерно и срок.
  Занятость, переходы между этапами, завершение и начисление очков подтверждает хост.
  Одновременный старт имеет одного исполнителя, повторный результат не даёт вторую награду.
- Для мира введены стабильные id. Передаются изменения предметов, дверей, коллизий, разрушаемого,
  транспорта, котов/жителей и подвижных узлов. Рисунки небольших изменяемых CanvasTexture тоже передаются.
- Подбор, бросок, посадка, захват, двери и обычные взаимодействия проходят через хоста.
  Владелец транспорта предсказывает управление локально; хост проверяет его перемещения и занятость.
- Событие города выбирает хост. Гости создают его модели по общему рецепту и получают состояние.
  Тот же источник определяет таймер, очки, места, награды и выбранный повтор финала.
- Добавлены передача выстрелов и дронов; для разрушения университета передаются снятие коллизий и руины.
  Стабильные каталоги зданий и точек миссий сохраняют ссылки после удаления объектов.
- Движение игрока и проверка сетевых перемещений выполняются мелкими шагами: быстрый шаг
  не должен перескакивать через тонкую стену. Физические коллизии обновляются отдельно от сглаживания картинки.
- Переподключение в течение 8 секунд сохраняет id игрока. Новый участник в середине матча
  остаётся в хабе до следующего запуска и не останавливает уже идущий матч.

## Как устроен обмен и где границы

Хост браузера остаётся источником общих решений. Интерактивную мини-игру считает её исполнитель,
чтобы движения мыши не ждали интернет; её объекты и результат поступают хосту в рамках выданной попытки.
Это схема для компании друзей. Полной серверной симуляции и защиты от поддельного прохождения мини-игры нет.

Положения людей передаются до 10 раз/с, изменения мира - до 5 раз/с в том же сообщении.
События ввода объединены с состоянием. Неподвижная карта не отправляется заново; каждые 3 секунды
передаётся восстановительный снимок отклонений от исходного мира. Есть ограничение очереди отправки,
номера кадров и раунда, отбрасывание старых сообщений, проверка размеров пакетов и частоты на сервере.
В проверенном обычном сценарии очередное изменение мира составляло около 4.5 КБ; это не верхний предел.

Свёрнутая вкладка хоста ставит матч на общую паузу. При отсутствии снимков более 2.5 секунд
гость тоже останавливает симуляцию. После возобновления приходит полный снимок изменений.
Пауза уменьшает отправку до 2 сообщений/с; закрытие хоста завершает комнату после периода переподключения.
Непрерывную игру без вкладки хоста даст отдельная серверная симуляция, а не более частые таймеры браузера.

Мир общий в пределах раунда. Сохранение целого города между матчами/после перезагрузки страницы
не добавлено. Личный кошелёк фистов и коллекция скинов сохраняются прежним способом.
Частицы дыма, пыль и другие короткие косметические эффекты могут отличаться.

## Main / release и Cloudflare

Две ветки разделяют сайты, но сервер комнат пока один: его автоматическая сборка привязана к `main`.
Новый Worker сохраняет обработку старого протокола v0.60.2; версия комнаты не позволяет смешать разные клиенты.
Для полной изоляции теста от боевых комнат нужен второй Worker и отдельный адрес в тестовом клиенте.
Публикация `main` может перезапустить общий Worker, даже если `release` сайта не менялся.

По актуальной документации Cloudflare бесплатный Durable Objects: 100 000 запросов/сутки,
13 000 ГБ·с/сутки; входящие WebSocket-сообщения учитываются 20 к 1, исходящие отдельно не тарифицируются.
Для 8 игроков при 10 сообщениях/с и прикладном ping раз в 3 секунды это примерно 14 880 запросов/час.
100 000 / 14 880 = около 6.7 часа суммарно по всем таким комнатам, без учёта входов, переподключений,
и другого расхода аккаунта. Это расчёт по запросам, а не гарантия времени работы или FPS.
Hibernation API сохранён: периодические серверные тики, запись состояния мира в SQLite на каждом кадре
и дополнительная база данных не добавлены.

Источники: https://developers.cloudflare.com/durable-objects/platform/pricing/
и https://developers.cloudflare.com/durable-objects/best-practices/websockets/ .

## Проверки и следующий шаг

- `npm run build` - сборка клиента.
- `npm run test:online` - детерминированная случайность, восстановительный снимок, конфликт попыток,
  повторная награда, движение через стену; настоящий локальный Cloudflare runtime проверяет
  маршрутизацию, полномочия хоста, версию, сохранение id и старый протокол.
- `scripts/online/smoke.html` - два отдельных клиента через локальный Worker, шесть ботов плюс друг:
  карта/коллизии/предметы, одинаковые миссии, конфликт подбора, дверь, пауза, конфликт задания,
  прохождение пазла гостем, однократная награда, общий городской ивент, финальная таблица.
  Дополнительные сценарии - конфликт посадки в транспорт, выбывание гостя и выстрел дрона.

В этой среде WebGL отключён. Браузерный тест использует реальные THREE-геометрию, raycast, DOM,
физику и сеть с подменой только рендера. Тестовый renderer существует исключительно на dev-странице
и не попадает в production. Это не проверка картинки, GPU, 144 FPS или двух живых людей по интернету.

Перед выкаткой: сыграть вдвоём из разных браузеров/сетей на `main`; проверить транспорт, захваты,
разрушения, автобус, сложные цепочки миссий, полицейскую клетку, все общие события и повтор.
Автоматическая проверка не покрывает каждую из многочисленных миссий и каждый предмет.

Локально: `npm ci`, затем `cd worker && npm ci`, вернуться в корень, `npm run test:online`.
Для CPU-сценария открыть `/scripts/online/smoke.html` на dev-сервере. Тестовый маршрут автоматически
поднимает локальный Miniflare; опубликованная игра его не содержит и настоящие лимиты Cloudflare не тратит.
